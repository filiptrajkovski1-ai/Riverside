# Riverside Residence

Апликација за продажба, сопственици и договорени измени. Сите 55 станови се прикажани по катови. Со клик се отвора посебен картон со статус, сопственик, телефон, забелешки и основа врз која се цртаат линии и се поставуваат точки со опис.

Има и 55 паркинг-записи од табелата. Брошурата PDF ги прикажува првите 30 паркинзи, како во изворната брошура.

## Почетни податоци

Податоците се преземени на 21.11.2026 од листот Prodazba во 2025-09-29_Baza na podatoci Zgrada Kavadarci.xlsx. Сопствениците, забелешките и статусите се пренесени во private-import/02_seed_private.sql. Табелата нема посебна колона за телефон и тие полиња се празни.

Изворната база останува на следниот линк.

https://deltaf2-my.sharepoint.com/personal/info_deltaf2_mk/Documents/Zgrada%20Kavadarci/2025-09-29_Baza%20na%20podatoci%20Zgrada%20Kavadarci.xlsx?web=1

По почетниот увоз уредувањето се врши рачно во апликацијата. Заедничките записи се чуваат во Supabase. Копчето „Освежи“ ја презема последната состојба од колегата. Пред зачувување се проверува верзијата на записот и се пријавува судир ако некој веќе го изменил.

## Поставување

1. Распакувај го ZIP-от и создај **Private** repository во GitHub. Во него постави ги сите папки и фајлови од пакетот. Папката private-import содржи лични податоци од базата и треба да биде достапна само во приватното репозиториум.
2. Во Supabase создај нов проект. Отвори SQL Editor и изврши database/01_schema.sql.
3. Во SQL Editor изврши private-import/02_seed_private.sql. Повторно извршување ги остава постојните записи.
4. Во Authentication > Users создај две сметки со е-пошта и лозинка, една за секој од вас. Секој нека ја постави својата лозинка преку сопствениот уред. Во конфигурацијата на Auth исклучи „Allow new users to sign up“.
5. Во database/03_access.sql замени YOUR_EMAIL@example.com и COLLEAGUE_EMAIL@example.com со двете постоечки адреси. Изврши го SQL-от. Само тие две сметки се доделуваат во двата слота за пристап.
6. Во site/config.js внеси го Supabase Project URL и publishable клучот. Може и legacy anon клуч. Користи ги вредностите од Supabase Project Settings > API. Secret и service_role клучевите се административни и треба да останат надвор од апликацијата.
7. Во GitHub отвори Settings > Pages и избери GitHub Actions. Пакетот веќе содржи workflow што ја објавува само папката site.
8. Во Actions следи го „Deploy Riverside portal“. Откако ќе заврши, отвори го URL-от во Settings > Pages.
9. Најави се со првата сметка, провери ги податоците, па провери ја и втората сметка од друг прелистувач.

GitHub Pages од приватно репозиториум бара план што го поддржува тоа, на пример GitHub Pro или Team. Ако профилот го нема тој тип на Pages, папката site може да се постави на друг статичен хостинг со HTTPS, додека репозиториумот останува приватен.

## Пристап и објавување

Репозиториумот содржи податоци за сопственици во private-import. Workflow-от објавува само site. Во site се содржани кодот и сликите од продажната брошура. Сопствениците, телефоните, забелешките, статусите и цртежите се вчитуваат од базата по најава.

Објавените GitHub Pages страници и нивните статични слики вообичаено имаат јавен URL. Пристапот до личните записи се проверува во Supabase. SQL-от вклучува Row Level Security и дозволува читање само на двете доделени сметки. Промените одат преку save_portal_unit, која проверува членство, влезни вредности и тековна верзија. Директно запишување во табелата преку клиентскиот API нема доделени дозволи.

Сопствениците на административниот Supabase проект имаат административен пристап до базата. Отстранување на корисник од portal_members му го укинува пристапот до записите.

## Работа

- Прегледот содржи по еден ред за кат, со 11 станови во редот. На потесен екран редот се лизга хоризонтално.
- „Слободен“, „Резервиран“ и „Продаден“ се уредуваат во картонот. Последните два статуса користат иста црвена ознака во прегледот и брошурата.
- „Точка“ поставува нумерирана белешка на основата. „Цртај“ овозможува слободна линија со опис.
- „Избери“ отвора постојна белешка. „Избриши ознака“ отстранува цртеж или точка. „Врати цртеж“ ја враќа последната измена во тековното уредување.
- „Зачувај промени“ ги зачувува и полињата и цртежите на станот заедно.
- „Брошура PDF“ создава PDF со црвени рамки на страница 4 и средни линии кај броевите на становите на нивните страници. Во продажната брошура се извезуваат ознаките за достапност. Внатрешните белешки и цртежи за измени се гледаат во картонот на станот.
- Ако се пријави судир, внесениот текст останува на екранот. Копирај го потребниот дел, преземи ја последната верзија и повторно внеси ја договорената измена.
- Одјавување ја затвора локалната сесија. Телефоните и белешките се чуваат во базата.

## Проверка пред редовно користење

Во изработката се проверени навигацијата, внесот, точка со белешка, зачувувањето и повторното вчитување во локална пробна средина. Вистински Supabase проект и двете кориснички сметки треба да се поврзат со чекорите погоре. Тие не се активирани во овој пакет.

По поставувањето провери дека првата и втората сметка го гледаат истиот запис, дека трета недоделена сметка нема пристап и дека промени направени од колегата се појавуваат со „Освежи“.
